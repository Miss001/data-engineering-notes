## 1 事务

事务就是一系列的操作集合，即一个程序的执行单元。事务本身不包含四个特性，

我们需要通过某些手段，尽可能让这个执行单元满足四个特性，此时我们就可以称它为一个事务，或者说是一个正确的事务。

**原子性** ：一组操作作为整体执行，要么全部成功，要么全部失败（实现：mvcc+undo log）

**一致性**：事务开始和完成，数据保持一致

**隔离性**：事务之间相互独立

- ==隔离级别==

  t表有id,x两个字段，id=1的x值为’0’

  | 事务A：                                 | 事务B                        |
  | --------------------------------------- | ---------------------------- |
  | T1   begin;                             | begin;                       |
  | T2    update t set x =’abc’ where id=1; |                              |
  | T3                                      | select x from  t where id=1; |
  | T4    commit;                           |                              |
  | T5                                      | select x from  t where id=1; |
  | T6                                      | commit;                      |

   读未提交：一个事务所作的修改还未提交，其他事务就可以看见

  ​       (事务B： t3时刻查询结果返回abc)

   读已提交：一个事务所作的修改，必须等到提交后，其他事务才可以看见

  ​      (事务B ：t3时刻查询结果返回’0’，t5时刻查询结果返回’abc’)

  ​    每次执行sql都会重新拿取一致性视图

  可重复读：事务启动之后（执行第一个sql操作时才算正在的启动，不是begin 或start transaction 时），看到的值至始至终都是一致的

  ​       (事务B ：t3时刻查询结果返回’0’，t5时刻查询结果返回’0’)

     第一次执行sql时会拿取一致性视图，之后不再拿取

   串行化：一个事务执行时，对该行记录针对读操作加读锁，对写操作加写锁，当出现锁冲突时，一个事务必须等待另一个事务结束后才可以执行。

**持久性**：事务一旦成功提交，即使出现异常故障也不会丢失数据

## 表锁

1.通过非索引字段检索数据，加表锁

2.使用索引字段检索数据，但实际全表扫描，加表锁

### 意向共享锁（IS）&意向排它锁（IX）

意向共享锁：事务在获取表中某一行的共享锁前必须先获取到意向共享锁或者更高级别的锁

 加锁方式：lock table tmp1 read

 解锁方式：unlock table

意向排它锁：事务在获取表中某一行的排它锁前必须先获取到意向排它锁

加锁方式：lock table tmp1 write

解锁方式：unlock table

### 自增锁

所有的insert操作都会排队等待这个自增锁来获取自增值。

只发生在insert操作时；与事务无关，insert结束锁释放。

## 行锁

作用在索引上而非数据本身

使用相同的索引值检索不同的行，引发锁冲突

若一条sql没有走索引，则在每一条聚集索引后加X锁

### 共享锁（S）&排它锁（X）

1.共享锁：阻塞其他事务对该记录修改,其他记录不影响

加锁方式：select * from tmp1 where id=1  lock in share mode;

影响语句：select (但由于存在快照读，普通select不加任何锁)

 

2.排它锁：阻塞该事务对该记录查询和修改,其他记录不影响

加锁方式：select * from tmp1 where id=1  for  update;

影响语句：insert update delete(当前读)

 

3.冲突情况：

如果T1已经加了 S Lock ,那么T2在同一行上面可以加S Lock

如果T1已经加了 S Lock ,那么T2在同一行上面不可以加X Lock,T2被阻塞

如果T1已经加了 X Lock ,那么T2在同一行上面不能加S Lock或X Lock,T2被阻塞,T2只能等待T1释放锁

### 实现方式

#### 记录锁（record lock）

 只有在使用主键或唯一索引列查找数据时才会对该索引记录加记录锁

 加锁范围： 索引记录本身

#### 间隙锁（Gap lock）

间隙锁只存在于RR及以上的隔离级别

在使用非唯一索引检索数据时，才会对该索引之间间隙加间隙锁；

#### 插入意向锁

是一种间隙锁，只发生在insert操作时。

当insert操作发生时,会尝试在指定索引的间隙上加插入意向锁；若两个插入操作都加在同一个间隙上,而这个间隙之前没有其他种类的间隙锁,这两个插入操作都会成功设置插入意向锁且不会互相阻塞.

#### 临键锁(Next-key lock)

是recored lock 与gap lock的结合：锁住记录本身也锁住索引间隙
