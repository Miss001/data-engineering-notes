##  分库分表

分布在同一台主机上不同数据库的表，可以进行JOIN查询操作。 

分布在不同主机上的数据库中的表，不可以进行JOIN查询操作。

### 2.2.1 应用场景

**分库**

1）单磁盘容量剧增

2）高并发场景，单机无法满足

**分表**

1）单表数据过大，查询性能过低

### 2.2.2 表类型

**全局表**

1）全局表的insert、update、delete操作会实时地在所有节点同步执行，保持各个节点数据的一致性

2）全局表的查询操作会从任意节点执行，因为所有节点的数据都一致

3）全局表可以和任意表进行join操作

```
#定义
<table name="tb_global"  dataNode="dn1,dn2,dn3"  primaryKey="ID"  type="global" /> 
```

**普通表**

```
#定义
<table name="tb_normal"  dataNode="dn1,dn2,dn3"  primaryKey="ID" /> 
```

**ER表**

基于ER关系（实体关系模型）的数据分片策略，子表的记录与其所关联的父表的记录存放在同一个数据分片中，

通过表分组(Table Group)保证数据关联查询不会跨库操作。

```
<table name="tb_parent" dataNode="dn$1-2" rule="mod-long" >
  <childTable name="tb_child" primaryKey="id" joinKey="parent_id" parentKey="parent_id"/>
</table>
```



### 2.2.3 分片规则

==未定义分片范围根据defaultNode属性配置默认节点，否则写入数据会报错。==

- **范围分片**（auto-sharding-long）

  根据autopartition-long.txt 文件内容分配。表示为0-10条记录在第一个节点，11-20条记录在第二个节点等

  ```
  0-10=0
  11-20=1
  ```

  `使用场景`：

  1）ID分片：适用于根据长整型ID字段进行分片的场景，如用户ID、订单ID等。

  2）时间戳分片：适用于根据时间戳字段进行分片的场景。

  `缺点`：热点问题

  

- **取模分片**（mod-long）

  对指定的字段值进行取模运算（%），然后根据运算结果将数据路由到相应的分片

  `使用场景`：

  1）ID分片：适用于根据长整型ID字段进行分片的场景，如用户ID、订单ID等。

  2）均匀分布：适用于需要均匀分布数据的场景。

  `缺点`：批量写入问题

  

- **范围取模分片**（auto-sharding-rang-mod）

  根据partition-range-mod.txt文件内容配置，先字段值取模运算，后根据结果区间确定具体的分片节点

  ```
  0-32=0
  33-64=1
  ```

  `使用场景`：

  1）时间范围分片：适用于需要根据时间范围对数据进行分片的场景，如按月、季度等时间段分片。

  2）数据均匀分布：结合了范围分片和取模分片的特性，能够在保持分片均匀性的同时灵活应对不同范围内数据的分布情况。

  `缺点`：范围查询跨库影响

  

- **枚举分片**（sharding-by-intfile）

  根据partition-hash-int.txt文件内容配置。表示为分片字段值为1在第一个节点，值为2在第二个节点等

  ```
  1=0
  2=1
  ```

  `使用场景`：

  1）自定义映射：适用于需要根据复杂映射关系进行分片的场景，如业务逻辑定义的特殊分片规则

  `缺点`：枚举值字段值变更需要手动调整规则

  

- **pattern分片**（sharding-by-pattern）

  基于数据字段的模式（Pattern）来进行分片。

  `使用场景`：

  1）模式匹配分片：适用于根据数据字段的模式来进行分片的场景，如根据产品编号的前缀分片、根据用户地理位置分片等。

  2）业务特征分片：根据业务特征将数据分片。

  `缺点`：枚举值字段值变更需要手动调整规则

  

- **按指定时间格式分片** （sharding-by-month、sharding-by-date、sharding-by-hour）

  根据指定的时间格式进行数据分片

  `使用场景`：

  1）时间分片：适用于需要根据时间字段按指定月、天、小时分片的场景。

  

- **跳跃一致性hash**（Jump Consistent Hashing）

  对分片字段进行哈希计算，得到一个哈希值。利用 Jump Consistent Hashing 算法确定哈希值对应的分片节点。该算法通过哈希值和预定义的分片数，计算出数据应存储的节点。

  `使用场景`：

  1）分布式缓存：适用于分布式缓存系统，如分布式 Redis 集群，保证数据均匀分布和高可用性。

  2）大规模数据分片：适用于大规模数据存储，保证数据均匀分布和系统扩展性。

  3）负载均衡：适用于需要动态增加或减少分片节点的系统，保证负载均衡和数据迁移最小化。

  

- **crc32slot分片算法**

  对分片字段（如 `id`）进行 CRC32 哈希计算，得到一个哈希值。将哈希值对分片数量（如 2）取模，得到一个分片索引。根据分片索引将数据路由到相应的分片节点。

  `使用场景`：

  1）id数据分片：适用于根据ID进行哈希分片，保证数据均匀分布。

  3）大规模数据：适用于需要将大规模数据均匀分布到多个分片节点的场景。

  

- **字段子串分片**（sharding-by-substring）

  根据字段的子串值将数据分配到不同的分片节点上。

  `使用场景`：

  1）手机号码分片：根据手机号码的前缀进行分片，例如按照地区区号分片。

  2）地区编码分片：根据地区编码的前缀进行分片，例如按照省份代码分片

全局序列的配置（mycat数据库中设置，物理数据库）

```
DROP TABLE IF EXISTS MYCAT_SEQUENCE;
CREATE TABLE MYCAT_SEQUENCE (
NAME VARCHAR (50) NOT NULL,
current_value INT NOT NULL,
increment INT NOT NULL DEFAULT 100,
PRIMARY KEY (NAME)
) ENGINE = INNODB ;

-- 插入表数据
INSERT INTO MYCAT_SEQUENCE(NAME,current_value,increment) VALUES ('TMP_SCY', 0, 1);

-- 创建函数
DELIMITER $$
CREATE FUNCTION mycat_seq_currval(seq_name VARCHAR(50)) RETURNS VARCHAR(64)
DETERMINISTIC
BEGIN
DECLARE retval VARCHAR(64);
SET retval='-999999999,null';
SELECT CONCAT(CAST(current_value AS CHAR),',',CAST(increment AS CHAR)) INTO retval FROM
MYCAT_SEQUENCE WHERE NAME = seq_name;
RETURN retval;
END $$
DELIMITER ;

DELIMITER $$
CREATE FUNCTION mycat_seq_setval(seq_name VARCHAR(50),VALUE INTEGER) RETURNS
VARCHAR(64)
DETERMINISTIC
BEGIN
UPDATE MYCAT_SEQUENCE
SET current_value = VALUE
WHERE NAME = seq_name;
RETURN mycat_seq_currval(seq_name);
END $$
DELIMITER ;

DELIMITER $$
CREATE FUNCTION mycat_seq_nextval(seq_name VARCHAR(50)) RETURNS VARCHAR(64)
DETERMINISTIC
BEGIN
UPDATE MYCAT_SEQUENCE
SET current_value = current_value + increment WHERE NAME = seq_name;
RETURN mycat_seq_currval(seq_name);
END $$
DELIMITER ;
```
